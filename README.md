# 双人成行（双向摄像头互传）

两台安卓设备**同时采集本机后置摄像头并互传实时画面**：每台设备既发送自己的 H.264 视频流，又接收并渲染对端画面。纯 Kotlin + 原生 Android API，**零服务器、零流量费**。

**横屏 VR 模式（默认）**：App 强制横屏全屏，画面通过 OpenGL 渲染为**左右两个相同的完整画面（左右眼分屏）并带桶形畸变**，把手机横放入 Cardboard 类 VR 眼镜盒后，两人即可互相看到对方的第一视角，适合户外同场游戏。连接前显示的是**本机摄像头的左右分屏预览**，可以先戴好盒子对焦、确认效果，等对方连上自动切成对方视角。

> 本版本（2.3）专注**现场连接**：没有远程/公网模式，目标是"打开就能连、连上就出画面、戴上就能看"。

## 一、技术栈

| 环节 | 方案 |
|---|---|
| 视频采集 | CameraX，后置摄像头，1080P / 720P 可选（默认 1080P）@30fps |
| 视频编码 | MediaCodec 硬编码 H.264；1080P 4.5Mbps / 720P 2.5Mbps，I 帧间隔 2 秒 |
| 传输 | UDP Socket，H.264 裸流自定义分包（每包 1400 字节） |
| 发现 | UDP 广播（8889 端口）：全局广播 + 各网卡子网广播双发，自动配对 |
| 视频解码 | MediaCodec 硬解码 H.264 |
| 远端渲染 | OpenGL ES（GLSurfaceView），左右眼双画面 + 桶形畸变 |
| 屏幕 | 强制横屏、全屏沉浸、屏幕常亮、最高亮度 |

## 三、编译与安装

1. 安装 **Android Studio（Koala 2024.1 或更新版本）**。
2. `File -> Open` 选择本 `WiFiCameraP2P` 目录，等待 Gradle 同步。
3. 两台安卓手机（Android 10 / API 29 及以上）开启「开发者选项 -> USB 调试」，点 **Run** 安装；
   或 `Build -> Build Bundle(s) / APK(s) -> Build APK(s)`，把 `app/build/outputs/apk/debug/app-debug.apk` 装到两台手机。
4. 首次启动允许 **摄像头** 权限（网络权限是普通权限，不弹窗）。

命令行构建（Windows）：

```bat
set JAVA_HOME=C:\Program Files\Microsoft\jdk-17.0.21.21-hotspot
gradle assembleDebug
```

签名固定用工程内 `keystore/debug.keystore`（口令 `android`），任何人构建出的 APK 签名一致，可互相覆盖安装。

## 四、使用（3 步）

1. 两台手机连**同一个 WiFi**，或一台开热点、另一台连上（点【开热点】/【连热点】会跳到系统设置）。
2. 两台都打开 App，点 **【开摄像头】**：此时画面就是**左右分屏的本机预览**，可以先戴上眼镜盒对焦、确认 VR 效果。
3. 等状态栏变成 `已连接 192.168.x.x，正在显示对方第一视角`，画面自动切到对方视角。

不需要输 IP、不需要点"连接"——App 启动后就在后台自动搜索对方（状态栏显示"正在自动搜索对方…"），发现后自动建连、自动补发 SPS/PPS、自动请求关键帧，**通常 1 秒内出画面**。

| 按钮 | 作用 |
|---|---|
| 开摄像头 | 启动后置摄像头采集，画面立即以左右分屏显示（连接前也能预览 VR 效果） |
| 画质 | 1080P（默认）/ 720P 切换，切换会重建编解码并重启采集；两端建议选同一档 |
| 选择镜头 | 枚举后置镜头，可强制切到超广角（机型支持时） |
| 重新搜索 | 手动重新发起发现（一般不需要，断开后会自动重连） |
| 沉浸 | 一键隐藏顶部状态条和底部按钮，只留画面；**再点一下屏幕任意位置退出** |
| 开热点 / 连热点 | 跳到系统热点/WiFi 设置 |
| 断开 | 停止发送、关闭摄像头、恢复本机预览 |
| 日志 | 查看/导出运行日志 |

**自动重连**：连接后如果 6 秒收不到对方任何数据包，App 会自动重新搜索并重连，不需要手动操作。

## 五、分包协议

- 包头 13 字节：`magic(2) + flags(1) + frameId(4) + totalSize(4) + chunkIdx(2)`；
- `flags`：bit0=帧首包、bit1=帧尾包、bit2=SPS/PPS 配置帧；
- 每包载荷最大 1387 字节；接收端按 `frameId + chunkIdx` 重组，收齐帧尾包且字节数完整后投递解码器；
- 超过 1 秒未收齐的帧直接丢弃（统计为丢帧），等待下一个 I 帧（每 2 秒一个）恢复画面；
- 发送端缓存 SPS/PPS，`setTarget` 时立即补发，避免对端解码器晚启动时黑屏。

## 六、现场连接优化（2.1 / 2.2）

| 优化 | 效果 |
|---|---|
| 启动即自动搜索 | 用户只需要点"开摄像头"，不再手动点连接 |
| 全局广播 + 各网卡子网广播双发 | 减少"某些机型收不到 255.255.255.255"导致的搜不到 |
| 本机地址缓存 3 秒 | 不再每个广播包都遍历网卡，降低耗电/卡顿 |
| 前 4 秒 400ms 快速搜索 | 连上的等待时间从 1~2 秒降到 0.5 秒左右 |
| 发现后补发 SPS/PPS + 请求 IDR | 连上立即出画面，不再黑屏等 2 秒关键帧 |
| 每 3 秒补发一次 SPS/PPS（2.2） | "先连上、后开摄像头"也不会黑屏 |
| 6 秒无包自动重连 | 对方重启/走远后自动恢复，无需手动 |
| 收到数据包也兜底学习对端地址 | 广播偶发被丢弃时仍能连上 |
| 状态栏显示 kbps / 丢帧 / 双向 FPS | 弱网问题一眼可见 |
| **按视频宽高比信箱化（2.2）** | 16:9 画面不再被塞进方形眼窗拉伸变形 |
| **发现线程代际隔离（2.2）** | 修复自动重连时新旧发现线程互相干扰、偶发"一直搜不到" |
| **8888 端口被占用时不再崩溃（2.2）** | 状态栏提示，而不是闪退 |
| **连接前即左右分屏预览（2.3）** | 本机摄像头直接进 VR 渲染，先对焦摆位，不用等连上 |
| **一键沉浸（2.3）** | 隐藏状态条和按钮，只留画面；点屏幕任意位置退出 |
| **画质档位（2.5）** | 默认 1080P，可切 720P；切换会重建编解码并重启采集 |


## 七、已知局限

1. **UDP 不保证可靠传输**：信号差、拥塞或距离过远会丢包，表现为花屏/马赛克/绿块，通常在下一个 I 帧（≤2 秒）自愈；这是低延迟方案的取舍，不做重传。
2. **仅限同一局域网**（同一 WiFi 或热点）。跨网络（4G/异地）不可用——那是需要服务器的远程方案，本版本已移除。若路由器开启了 **AP 隔离/客户端隔离** 或使用访客网络，两台手机之间也会互相收不到，需要关掉。
3. 不做码率自适应：网络变差时不会自动降码率（可在 1080P/720P 之间手动切）。
4. 不录制、不保存任何视频，退出 App 后无任何媒体文件残留。
5. 左右眼显示的是**同一画面**（单摄像头无真实视差），VR 盒中是大屏沉浸效果，不是立体景深；桶形畸变是基础镜片补偿，未做色差校正。
6. 户外强光下屏幕可见度有限（已默认最高亮度）；长时间高负载会发热。
7. **机型镜头限制（实测 iQOO Neo10）**：该机超广角被封在系统相机私有接口，第三方 App 无法调用，只能用主摄（约 84° 视野）。低成本方案是加装夹式外置广角/鱼眼镜头；或换用对第三方开放辅助镜头的机型。
8. 部分国产 ROM 限制热点/后台网络，连接失败时先确认两台设备在同一网段。

## 八、功能边界

仅保留双向摄像头实时画面互传：**无聊天、无文件传输、无录像、无语音、无服务器、无手动 IP**。
